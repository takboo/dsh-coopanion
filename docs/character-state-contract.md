# API 2 可选角色状态：protocol 1

本扩展将选中会话的最小工作事实送到角色，供持续表演、请求等待和结算续接使用。Harness 的 Model、请求 Broker、Agent 运行状态与共享完成判断继续拥有事实；角色只做呈现。

## 兼容与选择

API 仍为 2，既有必需方法不变。角色在 `figure.json` 声明：

```json
{"extensions":{"dsh-coopanion":{"state":1}}}
```

本地清单读取器只识别 state=1。未声明、未知版本以及原有角色均保持原来的神态、动作词和控制字段，不接收新增数据。旧宿主忽略未知清单字段时仍可加载实验包，角色用原神态词降级，不凭一个 curious／worried 词制造持续的待处理请求。

## 快照

可信页面通过既有 `body.set({ companionState })` 传递完整快照。由 [character-state.js](../web/character-state.js)投影、校验并复制，只有下列字段进入角色沙箱：

| 字段 | 含义 |
| --- | --- |
| `protocol` | 固定为 1 |
| `sessionId` | 用户选中的完整会话身份；没有选中时为 null |
| `work` | 没有已观察工作时为 null；否则含下列工作元数据 |
| `work.id` | 会话身份与 turn 的完整元组编码，同一回合不因工具或模型尝试变化而改变 |
| `work.active` | 由现有 Host 活动恢复与 Agent 运行核对产生，历史未结束记录本身不证明仍在运行 |
| `work.stage` | focus／tools／report，分别为考量、工具执行、公开输出；请求神态不覆盖该续接意图 |
| `work.tools`、`seq`、`atMs` | 当前未返回工具计数、持久事件序号和最后已知源时间；实时流只更新必要阶段与时间 |
| `work.outcome` | 无结局时 null；否则为分类，及共享完成判断提供的可选目标 id／revision／round |
| `pending` | 当前会话完整未结算请求集合，每项只含完整 id、sessionId、kind、state；state 为 open 或 continued |
| `visible` | 页面与 Host 生命周期综合后的可呈现状态；隐藏、恢复中及挂起时为 false |
| `calm` | 减少动态偏好 |
| `generation` | 原生运行代数，用于恢复手势与请求呈现 |

投影跟随明确选择的会话。背景请求与背景工作不冒充当前任务；宿主原有聚合注意和 NPC 退让规则继续生效。

不传会话／提示词正文、工具名称／参数／结果、推理、请求预览、文件路径、provider 凭证或发送权限。解析器拒绝未知协议、无效身份、重复请求及无效数值，并去除未列字段；不会截短身份。完整请求集上限为 4096。

## 连续性与事实所有权

事件及源时间即时更新；角色使用宿主 `step(dt)` 作为唯一动画时钟。工具往返改变段内节律，重复快照不重播工作开场；持续时间不判断真实长考。

工作身份从真实 turn/start 或生成流建立。Agent 的 running 状态可能先到，此时不制造 turn 0，也不重新激活已结束回合的身份；原有粗粒度神态保持兼容。

请求期间保留工作身份、阶段和表演续点。部分结算保留剩余身份；当前请求仍在时保持它；类型交接复用已确认标记交叠。全部结算后使用最新工作阶段或安静陪伴。打开提示、发送接受回执和角色触碰均不能结算请求。

首次恢复、切换会话、原生代数改变及隐藏恢复按当前事实建立等待，取消旧手势，不补播历史出场。配色与尺寸变化保留角色实例和工作身份。普通回复、目标继续和共享确认完成各自保留分类；实验包首轮不播放未确认的目标完成候选。

## 实现与验证

工作元数据由 [PetModel](../src/model.ts)产生，阶段独立于等待神态；请求集合来自已有 NotificationSnapshot。可信页面的扩展选择集中于 [pet.js](../web/pet.js)，沙箱消息协议和上游 body kit 均未修改。

实验包及构建命令见[小湛包说明](../examples/little-deep/README.md)。`tests/character-state.test.js` 覆盖工作身份、实时流、等待续接、隐私投影、完整请求身份与旧清单兼容；角色包导入与原生测试分别位于 `tests/little-deep-api2-ui.mjs`、`tests/little-deep-api2-native.mjs`。模型、安装、VM 与用户体验结果分别记录，当前进度从[设计入口](design/README.md)接手。
