# 角色产出工作流 v0

本流程供角色分镜、连续样片和产品接入复用。角色约束、已通过范围和下一步统一从[设计入口](README.md)读取；当前连续实例见[完成主线分镜 v2](storyboards/little-deep-completion-v2.md)，局部复做见[提问](storyboards/little-deep-work-v0.md)和[审批](storyboards/little-deep-approval-v0.md)。

事件先折叠为行为意图，再编排可持续的段落。普通工具往返共用工作段，公开汇报或待回应请求形成出口。源事件计时与动作计时独立，潜水表达集中工作；计时不确认模型长考。接入前的真实结构核对按[会话观察说明](session-observation.md)执行。

持续段保留自己的身份、进度和相位；请求临时接管身体，结算后采用最新事实。生活退让时取消未播放的旧计划。多个请求保留完整身份，当前请求结算后再交接；决定、工具结果与任务完成分别输入。

## 制作顺序与完成条件

| 阶段 | 要完成的工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 角色约束 | 明确固定造型、可变色区、表情范围、视角及素材来源 | 每个固定项有参考；变体仍能认出同一角色 |
| 能力核对 | 将微收、侧倾等表演用语对应到实际控制、单位和限制 | 每个关键动作标明已有、待补或本轮范围外；不能确定的观感有验证方法 |
| 分镜 | 画关键姿态，写明时间、动势、表情、附属物及承接 | 每段有起始姿态、持续运动和出口；含循环、打断及退出分支 |
| 关键表演验证 | 对影响理解的姿态或衔接制作短样片 | 在实际尺寸下能读出意图；反馈指出通过项或具体调整项 |
| 连续动画 | 按分镜实现时序、循环和动作交接 | 正常流程与异常打断均连续；减少动态、配色和尺寸下保持可读 |
| 产品接入 | 用正式事件驱动角色，复用现有事实判断 | 当前事件、请求结算及完成语义正确；按对应产品契约验证 |
| 复做与归纳 | 按同一流程再做一段，记录复用项与返工原因 | 文档能帮助重现制作步骤；将验证过的步骤纳入下一版流程 |

分镜静帧用于评审构图与关键姿态；连续性、节奏和“像在看我”的感受由短样片验证。进入实现的细节以当轮用户反馈为准，制作过程中持续更新对应分镜。

验收意图按实际可读性收敛。观众读出的“一怔、疑问浮现”可以成为有效表演，不因最初用语写了“看向用户”就强求对视；当前角色的具体目标由其分镜说明。

## 通用分镜规范

### 角色与画面

整段使用同一套角色设计。固定轮廓特征、身体比例、色区边界和眼型基准；表情、姿势和配色变化分别说明。配色变体使用同一造型，镜内换色需规定变化原因与过渡方式。

当前二维角色优先采用固定机位、固定构图尺度的连续分镜。写“转向正面”“独立歪头”前，先核对对应造型或局部控制能力。机位、比例或朝向变化也需要起止姿态及动作依据。

角色画面内不放说明文字。时间、事件、实现说明和运动箭头放在画外；问号、感叹号等作为图形附属物单独定义形状、锚点、出场和退场。正式产品的正文、审批及提问入口继续遵循产品契约。

附属物的出场要说明其自身如何变化，例如沿笔画逐步形成、最后落点和轻微颤动。形状、位置、描画时序及独立运动分别评审；涉及这些变化时提供可暂停的短样片。

连续样片与关键姿态对照使用同一套表演时序，关键姿态按时间采样，保持同一造型和控制来源。自动跨段保留同一个角色实例的当前姿态与速度；重播、暂停和进度定位属于查看控制，分别说明其行为。

### 动势与表情

每段至少保留一条连续动势，可由呼吸、漂浮、摆尾、水纹或附属物承担。主动作可以有意识地停顿，其他部位保持低幅运动；减少动态偏好允许压低或停用这些装饰运动。

表情从当前眼形逐步过渡到目标眼形，说明开合、眼睑、倾斜及大小关系如何变化。弹簧平滑只证明存在过渡；指定时长、是否回弹、与身体动作的先后仍由表演编排决定。

### 承接与交互

分镜节拍用于说明动作关系，可以重叠；不要求每个编号逐项串行演完。一次性出场与持续状态分开设计，高频工作提示尽早建立可读意图，等待不计入出场时长，余韵不阻挡真实交互。

每次切换由动作带出：上一段的收势成为下一段的起势。保留当前姿态和速度，明确减速、换向或展开过程，避免回到默认姿态再播放新动作。循环保留相位，重复事件按身份合并或更新持续状态。

分镜写出被触碰、拖动、新事件和请求结算打断后的去向。真实任务状态及时更新，表演从被打断的当前姿态继续；旧动作不能在新事件后延迟补播。页面隐藏时暂停装饰推进，恢复后按当前事实呈现。

## 每段分镜的复用格式

每段包含以下内容，具体镜头逐行记录在时间表中：

1. **意图与触发**：观众应读出什么；由哪项事实触发、何时失效。
2. **固定项**：引用角色设计与配色，说明本段机位、构图和尺寸。
3. **起始姿态**：身体、视线、尾鳍、表情、附属物及仍在延续的运动。
4. **镜头时间表**：时间范围、关键姿态图、运动方向与幅度、表情变化、附属物、承接方式。
5. **实现对应**：实际控制接口与单位；已有能力、待补控制及范围限制。
6. **持续与退出**：循环、条件满足、重复触发、新事件、触碰、拖动及减少动态分支。
7. **观看问题**：用可观察的问题评审，例如“疑问是否及时读得出”“侧倾像疑问还是失衡”。
8. **验证与结论**：检查覆盖的源码身份和环境、用户反馈、下一次仅需调整的内容。

时间表列采用：`镜头 / 时间 / 关键姿态 / 连续运动 / 表情与附属物 / 实现与承接`。时长、角度、位移和颜色属于候选参数，观看后再收敛。

## 能力与验证分开记录

实现状态使用“已有”“待补”“范围外”。验证分别记录源码核对、机制检查、浏览器画面、用户体验和产品宿主结果，避免把一个层面的通过推广到其他层面。特定角色的控制表保存在该角色分镜中，通用流程只维护记录方式。

关键验证绑定实际源码提交及未提交文件摘要；产品接入再记录实际宿主版本，打包验证再记录包摘要。静帧、样片、自动化、系统实机和用户审美分别给出结论，固定历史证据按[证据目录说明](../evidence/README.md)保存。

## 工作事件的来源

工作角色先把正式事件折叠为可表达的意图，再选择身体动作、表情与符号。事实来源复用 [PetModel](../../src/model.ts)、[完成判断](../../src/completion.ts)、[提醒契约](../notification-contract.md)和[会话契约](../session-chat-contract.md)。

普通回合回复、目标中间轮、确认的新目标完成分别呈现。工具失败与整个回合失败分别处理；发送接受回执与任务完成分别处理；关闭提示与审批或提问结算分别处理。符号退场不能改写真实请求状态。

需要接入角色包时，再按 [API 2 角色契约](../characters.md)补齐边界、交互、资源及降级行为。上游引擎及素材的来源与许可沿用相应来源记录。

## 接手与归档

当前状态统一维护在设计入口；单段分镜维护意图、约束、候选参数和验证结论。被用户反馈取代的分镜及其源码按需归档，附原路径与摘要，由索引明确其历史身份，并从普通搜索屏蔽。固定原始证据及第三方原文保留字节。

先在一个场景完成分镜、样片和反馈的闭环，再按同一流程复做其他场景。测试通过、实现完成与用户体验确认分别记录，流程随复做结果修订。
