# 小湛工作分镜 v0

更新于 2026-10-29。按[角色产出工作流](../character-production-workflow.md)制作。**W03 疑问浮现**核心出场约 1.5 秒，用户已确认出场、结算退场与交互接管；[审批场景](little-deep-approval-v0.md)现也已获用户确认。此前串行长版已归档，提问规范以本页为准。

## 意图与验收目标

小湛有件事想问你，稍微停一下，提出疑问，等你回应。可以保留“一怔、睁眼、疑问浮现”的感觉，神态偏好奇、稍有犹豫；避免把正常提问演成任务失败或持续茫然。

**不强求对视。** 眼睑和视线的小幅变化只辅助神态，不承诺观众会读成“看向我”。明确指向用户的回应可在后续轻戳、靠近和抚摸场景单独验证。

触发事实来自真实待处理提问，审批可用同一身体动作配感叹号比较。当前[视觉样片](../art-workflow/whale-little-deep-v3/storyboard.html#preview)仍是固定分镜，不接入 Harness 或结算请求。

## 角色和画面

固定造型以[当前设计入口](../README.md#固定造型)为准，全段复用现有鲸鱼轮廓、白腹、B 大小眼基准和实心尾鳍。采用固定机位及尺度，配色切换只作同造型对照；镜内全色盘渐变尚未实现。

画内保留角色和无底牌图形附属物。问号位于左侧头前，沿有机笔画逐步形成，弯钩先画、圆点最后落下，并有独立轻颤。时间、阶段名和说明放在画外。

## 交叠时序

分镜编号和节拍用于说明动作关系，不要求逐项串行演完。出场不包含额外的工作参照片头，等待也不计入一次性表演时长。

| 时间 | 身体与神态 | 符号与承接 |
| --- | --- | --- |
| 0–0.25 秒 | 稍微一怔，划鳍与身体横移减弱；眼睑同时逐渐打开 | 保留原有动势，侧倾提前进入，不等睁眼完成 |
| 0.15–1.05 秒 | 整体侧倾约 12°，尾部稍后跟随；漂浮继续 | 头前逐笔画出问号，圆点最后落下；问号自身轻颤 |
| 1.05–1.5 秒 | 身体稍回正，眼睑逐渐放松 | 符号保留，颤动减弱；衔接安静等待，弹簧余势自然落定 |
| 1.5 秒以后 | 低幅摆尾、呼吸、漂浮及偶发眨眼 | 等待真实处理，不重播出场、不撤掉待处理标记 |

当前控制目标在约 1.05 秒完成问号，约 1.5 秒接入等待；身体允许保留少量惯性余韵。时序与采样时刻由 [storyboard-performance.js](../art-workflow/whale-little-deep-v3/storyboard-performance.js)维护，三张参考帧来自同一表演的 0.12／0.70／1.5 秒。

## 实现能力与边界

| 表演 | 当前实现 | 边界 |
| --- | --- | --- |
| 收势、睁眼和侧倾交叠 | 同一 Actor 保留位置与速度；插值控制 `rootX`、`lean`、`tail`、`fin` 与眼形 | 交接候选覆盖 working／thinking／idle，正式事件适配待补 |
| 神态中的视线变化 | `lookAt(x, y)` 平滑改变双眼整体偏移，保留 B 大小眼基准 | 无独立瞳孔，不将回中等同于对视 |
| 约 12° 侧倾 | `lean.target` 峰值约 0.22 弧度，随后放松 | 整只鲸鱼旋转，没有独立歪头或正脸转身 |
| 问号／感叹号 | 共用路径长度控制笔画；候选中的问号跟随当前整体变换，结算后定住锚点淡出 | 局部拉伸不让符号跟着拉长；提问与审批样片已确认，正式角色接口待补 |
| 漂浮和眨眼 | 复用引擎呼吸、漂浮及原生眨眼 | 长期生命感、实际小尺寸及系统偏好需要体验 |
| 配色和符号对照 | 切换时保留当前进度和姿态 | 全色盘镜内渐变待补 |

绘制与查看控制见 [storyboard.js](../art-workflow/whale-little-deep-v3/storyboard.js)。重播和拖动进度会按同一种子与固定步长重建姿态；自动推进只使用一个实例。页面隐藏暂停推进，恢复不补播。减少动态时默认展示完成姿态，手动播放降低侧倾／划鳍／横移，关闭颤动。

## 本轮观看问题

1. 疑问是否更早成立？收势、睁眼和侧倾的交叠是否自然？
2. 约 1.5 秒是否简洁，同时保留逐笔成形、轻颤和余韵？
3. 神态是否好奇、稍有犹豫，而非出错或持续迷茫？
4. 头前位置、笔画风格及侧倾幅度在实际尺寸下是否清楚且不过分？

10 月 29 日用户确认“出场节奏可以，继续做结算退场和交互接管”。随后确认结算退场与交互接管，并在审批复做后确认“?和!通过了”；当前两段样片作为基线保留。旧长版和早期“必须看向用户”的假设从[归档说明](../../archive/2026-10-28-little-deep/storyboard-long-v0/README.md)追溯。

## 已确认的结算退场与交互接管

[交接样片](../art-workflow/whale-little-deep-v3/request-study.html)消费本地模拟的折叠状态。`sync({sessionId,mood,interactions})`只读取完整请求 id、所属会话、类型及 open／continued／settled；字段来源对应 [PetModel](../../../src/model.ts)和[请求契约](../../../src/notification-contract.ts)。目前只验证提问及 working／thinking／idle 三种承接，不连接 Host、不发送答复、不把模拟通过解释为真实结算接入。

| 触发／时间 | 身体、符号与承接 |
| --- | --- |
| 最后一个提问结算，0–0.36 秒 | 立即更新请求事实并接入最新持续动作。符号保留当前已画出的笔画，在结算时锚点轻轻上浮、缩小并淡出；不先补完问号，不等退场结束才继续工作 |
| 并存提问只结算一个 | 其余 id 继续等待，不收起标记、不重播出场；当前提问仍在时保持其身份 |
| 轻触／Enter，约 0.4 秒 | 眨眼、小幅柔和回应，身体出场可被接管；正在描画的符号继续完成。随后直接等待，不补播原来的侧倾 |
| 拉动与松手 | 真实轮廓弹性拉伸，松手不传抛掷速度。拖动保持用户拥有权；其间事实及时更新，松手按最新待处理请求或持续动作接回 |
| 退场中新提问 | 撤掉旧符号退场，从当前 Actor 的位置、形状和速度进入新出场；旧退场不会稍后撤掉新问号 |
| 拖动／隐藏时新提问 | 保留最新请求，恢复时直接进入等待，不排队补播旧出场 |
| 切换关注会话 | 清理当前手势，按新会话已有事实恢复等待；后台会话的提问不抢当前表演 |
| 减少动态 | 已有完整符号直接等待，降低身体幅度、关闭颤动和退场位移；请求结算仍然有效 |

打开／关闭提示、消息已接收、重复同步及 continued 状态都不能结算请求。这里不自行推断答复成功；只有输入事实显示该请求已结算或已不在完整待处理快照时才退场。接入 Host 时仍须由现有 Broker／投影拥有请求真相，不能把此处的模拟按钮移作实际结算入口。

实现通过节点机制检查，浏览器检查覆盖分别结算、提示与回执保留等待、画布拖动松手、键盘轻触和继续思考。用户于 10 月 29 日确认“这版结算退场和交互接管可以”。正式宿主、系统减少动态实机及物理设备仍分别验证。
