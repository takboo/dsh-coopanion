# 小湛审批分镜 v0

更新于 2026-10-29。按[角色制作流程](../character-production-workflow.md)复做第二个场景。**W02 下一步，需要你决定**沿用已确认的提问身体与交接机制；用户现已确认“?和!通过了”，本页当前审批样片作为已确认基线保留。真实宿主接入仍未开始。

## 意图与触发

小湛准备走下一步，发现需要你的决定，于是停一下、给出提示、安静等候。神态保持认真、平和；感叹号应像“这里需要确认”，避免惊吓、报警或责怪。

正式事实沿用[提醒契约](../../notification-contract.md)：`approval/asked` 与 `approval/decided` 按完整原生 id 配对，再由 Broker 提供请求状态。允许和拒绝都可结算对应审批；允许不证明工具执行或任务完成，拒绝不推断整个任务失败。当前样片仅模拟折叠后的状态，不发出任何真实决定。

## 固定项与起始姿态

沿用[当前角色约束](../README.md#固定造型与制作流程)、B 大小眼、无底牌蓝色笔画、固定机位与三套关键姿态。身体复用已确认的 1.5 秒动作：保留当前工作余势，收势、睁眼、整体侧倾交叠；不增加独立头部、对视或警报跳跃。

问号改为头前手绘感的感叹号，先画略弯的主笔，最后落圆点。短笔画约 0.8 秒完成，轻颤比提问弱；等待不循环重画。配色切换仍保持同一造型和 Actor。

| 项目 | 状态与接口 | 边界 |
| --- | --- | --- |

| 手势、隐藏与减少动态 | 复用已确认的接管机制 | 持续抚摸、长期体验、API 2 与原生窗口在范围外 |

## 持续、退出与打断

- 打开／关闭提示或“决定已发送”都保留待处理审批；只消费最终结算事实。未知 id 的决定不能移除其他审批。
- 并存审批逐个结算；审批和提问保留各自完整身份。当前请求存在时不因新请求抢演；当前结算后接下一个待处理请求。
- 轻触只回应用户，拖动不作允许或拒绝。拖住期间事实及时更新，松手按最新请求或持续状态接回，不抛掷、不补播旧动作。
- 退场中新审批取消旧退场，从当前姿态出场；切换会话恢复已有请求时直接等待。页面隐藏暂停装饰推进，恢复按当前事实呈现。
- 减少动态时直接显示完整标记等待，压低身体幅度，关闭轻颤及退场位移；允许和拒绝仍分别结算请求。

## 观看问题

1. 感叹号能读成“等你决定”，还是像出错或报警？
2. 简短笔画在约 0.8 秒内完成是否自然，最后落点是否清楚？
3. 允许／拒绝后的退场是否平和，能否自然接工作、思考或待机？
4. 并存审批、审批与提问换标记时，身体是否连续、剩余等待是否清楚？
