# 小湛普通工作主线分镜 v0

更新于 2026-10-29。**W01 普通工作主线**现按用户指定会话进行脱敏结构回放，支持重复工作循环及按需请求；已确认的[提问 `?`](little-deep-work-v0.md)和[审批 `!`](little-deep-approval-v0.md)继续复用。连续承接机制验证后，另补[目标完成候选](little-deep-completion-v0.md)。当前整体仍待体验确认，未连接真实 Harness、API 2 或原生窗口。

## 意图、事实与固定项

观众应读出：小湛凝神想一想，低头划鳍做事，再展开向你回应；需要你时停一下等，得到回应后继续。短事件发生时仍是完整鲸鱼，只有持续长考才潜下去留下尾巴。普通回复不喷水、不跳起庆祝。

事实边界沿用 [PetModel](../../../src/model.ts)、[请求 Broker](../../../src/notification-broker.ts)和[共享完成判断](../../../src/completion.ts)：收到输入、回合开始、工具进行中、生成回复及回合结束分别表达。发送接受回执不代表开始执行或完成。工具结果只是一步结果；仅共享判断确认的新目标完成能触发可选的目标完成候选。

沿用蓝色、白腹、额顶缺口、B 大小眼、实心尾鳍及[固定造型](../README.md#固定造型)，固定机位与构图。画内只放角色和 `?`／`!`，说明及时间放在画外。思考保留明显左右扫摆与侧转收窄。起始为低幅漂浮待机；同一 Actor 自动跨段保留形状、位置、速度、眨眼及粒子时钟。

## 当前结构回放与连续承接

### 本轮反馈与节奏修订

用户指出中间事件缺乏区分，且频繁快速潜入、浮出，观感“很鬼畜”。核对旧版默认 8 倍回放，身体切换 85 次，其中 42 段 thinking；许多段只有约 0.3 秒。0.28 秒保持和弹簧连续不能保证观看节奏成立。本轮将普通工作拆成完整鲸鱼的三种持续表演，按屏幕时间编排，不随事件倍速加快摆动。

| 镜头／时间 | 关键姿态 | 连续运动 | 表情与附属物 | 实现与承接 |
| --- | --- | --- | --- | --- |
| 凝神考量，短思考持续 | 保留身体、白腹和眼睛，轻收小鳍，略侧倾 | 尾鳍慢摆，身体基本原位 | 眼睑稍收，视线斜上，像在权衡 | 新增 considering；不因 step/end 或工具返回潜入 |
| 动手做事，工具成组进行 | 完整鲸鱼略向前、低头 | 小鳍和尾鳍有节奏地划动，幅度高于考量 | 专注、视线向前下方 | 新增 doing；工具短间隙 0.8 秒内沿用当前工作动势，普通姿态至少留 1.4 秒 |
| 组织并输出文字 | 完整鲸鱼抬起、展开，停下忙碌划动 | 尾鳍低幅慢摆，小鳍放松展开 | 睁眼、朝用户侧看，和低头做事区分 | 复用回复语义、重编主线专用 replying；文字开始优先显现，再保留可读的余势 |
| 集中工作段的潜入（重新分镜中） | 保留已选实心尾巴姿态作为段落能力 | 明显扫摆和侧转收窄 | 五官随原思考造型隐去 | 旧 4 秒触发与相应冷却规则已撤销；下一轮按工作段落评审，不按每条 thinking 事件潜入 |
| 需要你与继续 | 沿用已确认的 ?／! 身体和笔画 | 请求结算后接到最新的完整鲸鱼工作姿态 | 原标记淡出；不庆祝工具／审批 | 不改已通过的局部时序；不补播之前错过的动作 |

1.4 秒停留和 0.8 秒桥接是动画可读性的候选屏幕节拍。事实仍逐条即时显示，角色把短促事件折叠为可读段落。用户认为节奏改善，但失去潜水且整体变化不足；当前先按[工作／生活表演语法](little-deep-behavior-grammar-v0.md)重新设计段落，不能把当前三种微姿态视为主线体验已通过。

### 进行中会话的边界

用户追问如何判断正在进行的会话是否长考。已经完成的会话只用于重复验证，不能利用后面还会思考多久来倒排动作。控制器每次只接受当前折叠事实并推进计时：没有工具、文字输出或待处理请求时，持续 considering 才累计；新工具或文字切断这段连续计时，请求立即接管。未来事件如何改变，不得影响相同已发生前缀的姿态。

这里的 thinking 是当前 Model 投影，不是模型真实推理深度的证明。静默可能包含网络／服务等待。当前已删除 4 秒潜水推断，`advanceEventTime(ms)` 只更新源时间及阶段计量，`advance(seconds)` 只推进动作、笔画与可读停留。两种时钟独立，没有一边增长就快进另一边的隐式规则。新的只读日志观察器不能替代正式 Host 的实时流、Agent 状态与请求回调。

[当前回放页](../art-workflow/whale-little-deep-v3/work-study.html)沿指定会话完整的 655 条事件推进，不再强制播放一次固定的 `!`、`?`。原会话长 598.121 秒，默认 8 倍速约 75.8 秒；可切换 1／8／16／32 倍，画外同时显示原始时间、当前 seq、步骤、未返回工具数量、事实状态和身体动作。

| 事实／节拍 | 当前编排 |
| --- | --- |
| 重复 thinking／working／talking | 事实即时更新；身体保留同一 Actor、位置和速度。短促变化在完整鲸鱼的 considering／doing／replying 之间承接，普通姿态约 1.4 秒、工具短间隙约 0.8 秒，只保留最新目标 |
| 公开文字输出 | 额外导出 7 段文字输出的起止时间与所属步骤，不导出任何 token 或正文；允许过程说明后继续思考和工具工作，不提前收势 |
| 原始审批 | Broker 按完整 id 恢复 pending，只有 seq 374 的实际决定才退出。回放速度只影响观看时间，不创造超时结算 |
| 可选 `?`／`!` | 原会话没有正式提问。页面提供明确标注的附加模拟请求，用同一循环控制器检查任意阶段进入／退出；模拟请求单独结算，不能处理历史审批 |
| 真实结束分类 | seq 654 的共享 completed 保留为事实。默认“先看连续承接”停在该边界，不用普通收势替代它；“加入目标完成候选”才播放轻收势 → 开心喷水一次 → 待机 |
| 隐藏、暂停与定位 | 隐藏暂停源时间与动作，不补播后台段落；进度定位以同一种子和固定步长重建，清除附加模拟。自动播放不重建 Actor |

默认页有 6 张同源承接抽样；前三张从同一次回放中采样首个稳定的凝神、做事和回复段，后三张比较请求及后续承接，不另造静态姿态。局部工具错误继续按当前事实处理，不转成回合失败。异常回合分支及真实 Host 接入仍未实现。

结构文件由 [prepare-little-deep-session.mjs](../../../scripts/prepare-little-deep-session.mjs)只读生成，复用本仓库 Model／Broker／CompletionTracker。源数据是固定会话的事件结构与文字阶段时刻，不包含消息正文、工具参数／输出或推理文本；原始文件摘要沿用下方核对记录。再生成命令需要 Node 的 `--experimental-transform-types`，输出不覆盖已有不同字节文件：

```bash
node --experimental-transform-types scripts/prepare-little-deep-session.mjs \
  --source /absolute/path/to/session.v4.jsonl.zstd \
  --zstd /absolute/path/to/zstd \
  --output /new/path/structure.json
```

这只是离线投影。日志外的实时提问投影、流式实时协议和宿主安装兼容不能由该文件证明；本会话中缺少的 `?` 由显式模拟覆盖，不能记作真实会话验收。

| 接到工作、组织回复、普通收势 | 本轮新增主线专用循环动作 | 不改变原互动页动作，不承诺口型或独立头部 |
| 连续时序与关键帧 | 同一主线控制器按时间分段推进；关键帧使用同一种子重建至采样时间 | 自动跨段不重建；用户重播和拖进度属于查看控制，会显式重建 |
| 正式事实 | 本地固定分镜模拟回合、请求及后续状态 | 不发送消息、不提交决定，不推断真实目标完成 |

## 固定对照的退出与查看控制

- 思考、工具工作、组织回复在真实运行中按事实持续；本页秒数仅用于预演节奏。重复状态不重置其循环相位。
- 审批允许／提问答复由样片固定时间模拟，退场按已确认方式与下一动作重叠。拒绝、取消及混合请求的独立交互仍可从对应已确认样片体验，本轮不扩写整套异常分支。
- 连续样片提供重播、暂停、进度定位、分段定位、配色及两个片尾。切换路线／片尾重新从头预演；换色保留当前进度和 Actor。
- 页面隐藏暂停样片时间，恢复不补播后台经过的段落；已出现的请求恢复当前等待，不重新播放装饰开场。减少动态时默认暂停，手动播放保留状态轮廓变化、压低动作幅度并关闭符号轻颤。
- 本轮先验证主线分镜与连续观看，不新增持续抚摸、全流程拖动拥有权或真实后台会话接管。已有 `?`／`!` 手势样片继续保留。

## 本轮观看问题

1. 能否看懂“想 → 做 → 等你 → 继续 → 整理回复”，各段是否有必要且节奏自然？

4. 普通收势是否自然，没有误读成庆祝或任务失败？目标仍继续的片尾是否能接回下一步？
