# 小湛与 AI 角色设计白板

更新于 2026-10-28。当前实现、分支关系和启动方式以[设计入口](README.md)为准。这里维护用户的设计意图和待验证判断；旧研讨原文已进入[历史归档](../archive/2026-10-27-whale-studies/README.md)。

## 已确定的方向

- 体验目标是安静陪着工作、有自己性格的小生命。
- 角色应贴合 AI 概念，可扩展到 DeepSeek、GPT、Claude、Z.ai。当前先打磨 DeepSeek 鲸鱼；其余角色没有启动制作。
- 可以放下“大肥鱼”的完整二创造型，保留 DeepSeek 的概念关联。
- 当前主体采用小湛的蓝色与身体，结合奶泡的藏尾巴互动和墨鲸的原生眨眼；用户要求白腹、尾柄和分叉尾鳍更贴近所给 logo 参考。
- 本轮使用 Livelings skill 和原生引擎完成第三轮独立交互原型。用户决定下一轮沿此方向继续；这不等于最终美术或完整生活感验收。
- 2026-10-28 用户指定参考 DeepSeek Harness thinking 动画的尾巴造型与动作。后续反馈明确要求明显摆动、身体上的尾巴向新参考靠拢，而且两种尾巴都必须实心，避免与白腹的视觉语言冲突。当前按这项修正统一造型，并加入 GIF 式展开、侧转收窄与左右扫摆；动作是否贴合仍待用户体验反馈。

## 用户反馈如何解释

第一轮让用户觉得互动思路可行，但造型不讨喜。第二轮用户选择了上述组合，并指出 DeepSeek 辨识度不足。第三轮据此制作了完整互动；下一轮应根据用户实际体验继续收敛，而不是重新把三套候选都当成待选方案。

形象吸引力、AI 概念辨识度和鲜活感分别判断。程序可运行、十六格工作台或演示序列通过，都不能代替这三项体验。

用户指出“纯尾巴和完整鲸鱼的尾巴形状不一样”后，不能只凭共享原始路径判断一致。已发现整体重采样和摆尾分区旋转会改变最终轮廓；当前改为共享尾巴采样点、尾鳍整体旋转。静止展开轮廓要对齐核对，思考侧转的收窄仍是有意动作，体验反馈继续单独判断。

用户随后提供官方 logo，指出尾巴像强行拼接且比例不自然。此项反馈优先于技术对齐：不能把“两个轮廓一致”当成造型完成。当前采用 logo 卷起双叶、短弯尾柄和身体连续曲线；实心、共用轮廓与明显摆动继续保留，比例与连接观感仍由用户体验判断。

## 下一轮重点

已同意按“眼睛对照 → 藏尾巴完整表演 → 抚摸余韵”逐步体验。用户看过 B／C 动态后选择 B 大小眼，指出 logo 的眼睛应是小点，不是弯弯白斑；C 不再作为眼型方向。当前默认角色已采用 B，原版与 C 仅保留作对照。白腹保持辨识色块，额外小鳍不加回。大幅思考摆动继续保留，后续安静节奏主要针对待机视线和小动作频率。

当前续做已将藏尾巴拆为看你、收鳍缩身、藏下去、停尾、试探探头和放心出来；思考中触碰则回应后回去想。重复触碰不重启表演，切换状态可打断。当前等待用户体验这一段的节奏与探头造型；持续抚摸及松手余韵仍是下一步，尚未交付。

| 问题 | 看什么 |
| --- | --- |
| 是否更像 DeepSeek | 蓝色、额顶缺口、弧形白腹、尾柄与不对称分叉在常用尺寸下能否形成稳定联想 |
| 是否愿意常驻桌面 | 静止与安静漂浮时是否喜欢；细节与动作会不会显得拥挤或打扰 |
| 互动是否自然 | 眨眼、藏尾巴、抚摸后探头、拉伸松手及被工作状态打断后的衔接 |
| 能否持续制作 | 同一代码母版是否能稳定修改，不依赖反复重绘独立视角 |

## 保留的判断与开放问题

- 简单形象仍需要比例与表演设计；生活系统的内部复杂度不保证外部鲜活感。
- 制作工具、视觉风格与运行方式分别选择。当前继续代码原型；Blender 尚未成为实施路线。
- 将来扩展其他 AI 时，先确定用户认可的身份线索，再设计相符的形体和专属反应；共享视觉语言不要求只换颜色。
- 角色是否跟随实际工作模型切换，以及哪些生活感模块值得接回，仍按后续任务讨论，不从旧方案自动恢复。
