# 小湛工作分镜 v0

更新于 2026-10-28。采用 [角色产出工作流](../character-production-workflow.md)。当前先编工作行为的连续分镜，首段验证“忙碌收势 → 注意力转向用户 → 轻轻侧倾 → 等待”。

[视觉分镜](../art-workflow/whale-little-deep-v3/storyboard.html)使用现有角色与引擎，已将 A → B → C → D 接成 6.2 秒的连续样片。可重播、暂停、拖动进度及单看 C，配色和提问／审批附属物可切换。关键姿态从同一表演采样。新整段的节奏与观感待用户体验确认，鼠标竞争及真实事件接入仍待验证。

## 角色和画面固定项

造型约束以[当前设计入口](../README.md#已确定的设计约束)为准。全段复用现有 `whaleBody()`、白腹和 B 大小眼基准，保留同一尾鳍，不添加头部或腹鳍。当前分镜中尾部比例及旧藏尾表演仍保留待体验确认状态。

采用固定机位与固定构图尺度。首轮统一使用 Deep 蓝；奶白、初版小湛蓝和夜游作为同造型的静帧对照。镜内换色留到配色过渡能力补齐后验证。

画内只有角色和候选图形附属物。时间、方向、事件、控制说明和反馈放在画外。根据首轮反馈，符号改为无圆底的有机笔画，移至鲸鱼左侧头前，先画弯钩或竖线，再落下圆点；问号自身保留小幅颤动。用户已允许在此 C 版本上继续，当前整段沿用这套视觉基线，新增的前后交接仍待体验。

## 首段 W03 转向用户

**意图**：小湛正在做事，发现需要与你沟通，先收住动作，再把注意力转向你，最后安静等待。

**触发**：当前表达的任务产生待处理提问；审批复用该身体分镜，以感叹号区分。事实以[提醒契约](../../notification-contract.md)中的真实请求为准。

**起始姿态**：完整鲸鱼，认真划鳍、低幅摆尾，视线偏下，身体仍有漂浮。样片前 0.9 秒展示事件到来前的工作参照；0.9 秒开始收势，正式接入不需要等待这段参照。以下时长均为候选，A／B 留出减速与视线变化的观看时间，C 保留原有 2.4 秒时序。

| 镜头 | 时间 | 关键姿态 | 连续运动 | 表情与附属物 | 实现与承接 |
| --- | --- | --- | --- | --- | --- |
| W03 A | 0.9–1.5 秒 | 维持工作时的完整鲸鱼，划鳍缓下 | 原摆动相位持续推进，运动幅度下降，漂浮延续 | 专注逐渐松开，暂无符号 | 连续减弱 fin／tail 及身体横移，不瞬间归零 |
| W03 B | 1.5–2.2 秒 | 双眼从偏下位置回中，身体接近稳定 | 呼吸与尾部余势承接 | 眼睑逐渐打开，保留大小眼基准 | 视线与眼形目标连续变化，由分镜持有注意力 |
| W03 C | 2.2–4.6 秒 | 先微收再侧倾至约 12°，尾巴稍后跟随，最后稍回正 | 侧倾缓入，漂浮连续 | 左侧头前逐笔画出问号；弯钩先出现，圆点最后落下，符号自身轻颤；审批用同风格竖线与圆点 | 沿用 C 的 2.4 秒时序，按路径长度逐步绘制，无圆形底牌和整体淡入 |
| W03 D | 4.6 秒以后 | 从 C 的姿态稍回正，逐渐放松 | 低幅尾摆、漂浮、呼吸及偶发眨眼 | 眼睑放松，符号保留，独立颤动逐渐减弱 | 同一 Actor 承接，约 6.2 秒进入稳定等待，之后继续低幅生活运动 |

自动跨段保留同一个 Actor、弹簧位置及速度，不调用状态重播。四格参考由同一表演按时刻采样：A 为 1.2 秒、B 为 2.15 秒、C 为 3.16 秒、D 为 6.2 秒，因此 C 参考帧显示描画中的问号。重播与拖动进度属于查看操作，按同一种子及固定步长重建对应姿态；换配色和符号保留当前进度。

### C 样片局部时序

局部时间从 B 的正视姿态开始，整体分镜时间加上 2.2 秒；可通过“单看 C”复查原有局部表演。

- 0–0.12 秒先微收，随后缓缓侧倾，约 0.76 秒到达 12° 候选峰值；尾部比身体稍后跟随。
- 0.30–约 1.17 秒逐步绘制问号弯钩及下行笔画，随后短暂停顿，约 1.19–1.34 秒落下圆点。整体保持可见，不以缩放和透明度代替笔画生长。
- 1.32–1.98 秒身体稍回正，至 2.4 秒留下观察时间；整段模式随后进入 D，单看 C 则保持该段姿态及轻颤。暂停后保留当前画面。
- 页面隐藏时暂停推进，恢复后不补播隐藏期间的时间。减少动态偏好下默认呈现完成姿态，手动播放时降低侧倾并关闭颤动。

### 持续与退出

- 相同请求重复同步时保持等待，不重播开场；新的并存请求保留各自身份，图形如何合并在后续连续分镜中确定。
- 轻触时短暂回应后恢复等待，符号及真实待处理状态保留。连续触碰不能反复重置整段。
- 拖动时由直接操控接管身体，松手从当前姿态恢复；附属物跟随锚点，避免脱离或碰撞正文入口。
- 请求实际结算后，符号收起、侧倾回正，再按当前事实接回思考、工作或待机。打开源会话和关闭提示不视为结算。
- 新任务事件或异常打断时，及时更新语义，从当前姿态承接新表演。问题仍待处理时，即使回合结束，也保留其待处理入口。
- 减少动态时保留角色神态与清晰符号，降低侧倾、划鳍及身体横移，默认呈现完成姿态。页面隐藏时暂停样片推进，恢复后不补播；真实事件恢复时的对齐仍属于产品接入工作。

### 首轮观看问题

1. 从工作视线回中后，是否能读出“注意力转向我”？若不能，先调整视线和眼睑，再考虑是否需要其他造型能力。
2. 从 B 开始的侧倾是否更清楚，约 12° 的幅度是否像在询问，还是像身体失衡？
3. 无底牌的问号与感叹号能否融入当前画风，并在同一身体姿态上表达不同事件？
4. 左侧头前的位置是否合适，逐笔出现和独立颤动是否生动、是否过于急促？缩小后仍需检查遮挡及辨识度。
5. 整段中的收势、正视、侧倾、描画和回正是否自然？可在边界附近暂停、拖动进度或切换单看 C 比较。

## 工作流程的分镜覆盖

| 场景 | 需要串联的表演 | 当前阶段 |
| --- | --- | --- |
| W01 普通回复 | 待机 → 思考 → 工具工作 → 生成回复 → 收势待机 | 待编逐镜分镜；回复结束保持普通结果语义 |
| W02 需要审批 | 工作 → 收势 → 看向用户及感叹号 → 等待 → 继续 | W03 身体分镜的候选复用；结算后的承接待编 |
| W03 AI 提问 | 工作 → 收势 → 看向用户及问号 → 等待 → 继续 | 已实现忙碌至等待的连续分镜；新整段待体验，结算退场及交互接管待补 |
| W04 确认目标完成 | 工作／回复 → 开心展开及喷水 → 收势 | 待编；仅复用 `CompletionTracker` 确认的新目标完成 |
| W05 异常与停止 | 回合出错、阻塞／输出上限、中断、用户停止分别承接 | 待编；不把单个工具错误直接演成整个任务失败 |
| W06 交互与竞争 | 工作中轻触、重复触碰、拖动、新事件、背景会话提醒 | 待编；背景提醒不能任意抢走当前任务的整套表演 |

下一步先观看 A → D 连续样片，收敛收势、视线与进入等待的节奏；之后补结算退场和交互接管，再将同一制作步骤用于 W02 复做。持续抚摸及复杂空闲生活在工作行为分镜收敛后继续，旧藏尾反馈仍保留。

## 机制检查

运行 `node --test tests/little-deep-storyboard.mjs`，检查同一 Actor 跨段、姿态与目标轨迹连续、进度定位可复现、换色保留状态、C 独立范围及减少动态机制。浏览器检查显示、播放范围、暂停和拖动进度；用户对注意力、节奏和生命感的判断单独记录。实际系统减少动态偏好、宿主事件及物理设备仍需对应环境验证。
